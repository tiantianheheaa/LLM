# 一、项目背景与目标类问题

## 1. 你为什么要做这个 Qwen3 SFT 项目？

面试官想判断你是否只是“跑了个微调脚本”，还是理解业务问题。

可能追问：

- 这个项目解决的具体问题是什么？
- 为什么选择 SFT，而不是 RAG、Prompt Engineering、DPO 或 RLHF？
- 原始 Qwen3 模型在哪些场景下表现不好？

- 这个项目的成功标准是什么？
- 这个项目和业务指标之间有什么关系？

你需要准备：

> 我们不是为了微调而微调，而是因为基础模型在某些垂直场景中存在回答风格不稳定、领域知识表达不准确、格式不统一、任务遵循能力不足等问题。SFT 的目标是让模型学习高质量指令响应模式和领域任务范式。

# 三、SFT 原理类问题

## 3. 什么是 SFT？

可能追问：

- SFT 和预训练有什么区别？
- SFT 和 Instruct Tuning 是什么关系？
- SFT 的 loss 是怎么计算的？
- 训练时是否对 prompt 部分计算 loss？
- 为什么一般只对 answer 部分计算 loss？
- SFT 能解决什么问题，不能解决什么问题？
- SFT 会不会破坏原模型能力？
- SFT 和 DPO 的区别是什么？

核心回答方向：

> SFT 是在预训练模型基础上，用高质量的指令-回答数据继续做监督学习，让模型学习特定任务的输入输出映射。训练目标通常是自回归语言模型的 next-token prediction，但在 instruction tuning 中一般只对 assistant response 部分计算 loss，避免模型去拟合用户输入。

## 9. LoRA 原理怎么解释？

你需要能讲清楚：

> LoRA 的核心思想是冻结原始模型权重，只训练一个低秩增量矩阵。对于原始权重矩阵 W，不直接更新 W，而是学习 ΔW = BA，其中 A 和 B 是低秩矩阵。这样可以大幅减少可训练参数量和显存开销，同时保留基座模型原有能力。

可能追问：

- 为什么低秩矩阵能有效？
- rank 越大越好吗？
- alpha 和 rank 的关系是什么？
- LoRA merge 是什么？
- 推理时是否需要合并权重？
- 多个 LoRA adapter 能否切换？

## 11. learning rate 怎么选？

可能追问：

- LoRA 微调和全参微调 learning rate 有什么区别？
- 学习率太大会怎样？
- 学习率太小会怎样？
- 有没有做学习率搜索？
- warmup 有什么作用？
- scheduler 为什么选 cosine / linear？

回答方向：

> LoRA 只训练少量参数，通常可以使用比全参微调更大的 learning rate。学习率过大会导致 loss 不稳定甚至灾难性遗忘，过小则收敛慢或欠拟合。warmup 可以避免训练初期梯度波动过大。

## 12. batch size 和 gradient accumulation 的关系？

可能追问：

- batch size 对收敛有什么影响？

公式要记住：

```text
global batch size = per_device_train_batch_size 
                  × gradient_accumulation_steps 
                  × GPU 数量
```

## 13. max sequence length 怎么选？

可能追问：

- 序列长度对显存有什么影响？
- 为什么长上下文训练很贵？
- 如果样本超过 max length 怎么办？
- 截断 prompt 还是 response？

回答方向：

> max sequence length 需要根据任务输入输出长度分布决定。过短会截断关键信息，过长会显著增加显存和计算成本，因为 Transformer attention 复杂度与序列长度近似平方相关。

## 15. 出现过哪些训练问题？怎么解决？

面试官非常喜欢问这个。

你可以准备几个真实感强的问题：

### 问题 1：显存不足

解决方向：

- 减小 per-device batch size
- 增大 gradient accumulation
- 开启 gradient checkpointing
- 使用 LoRA / QLoRA
- 使用 bf16/fp16
- 降低 max sequence length
- 使用 DeepSpeed ZeRO
- 使用 flash attention

### 问题 2：模型输出格式混乱

解决方向：

- 检查 chat template
- 检查训练数据 role 标记
- 增加格式化样本
- 推理时统一 system prompt
- 加入格式约束评测

### 问题 3：模型过拟合

解决方向：

- 减少 epoch
- 降低 learning rate
- 增加数据多样性
- 增加 eval 集监控
- 使用 early stopping
- 加强数据去重

### 问题 4：模型变得啰嗦或幻觉增加

解决方向：

- 清洗低质量长答案
- 增加拒答、不确定性表达样本
- 控制答案风格
- 加入事实性评测
- 必要时结合 RAG，而不是只靠 SFT 注入知识

## 22. 基于 Instruct 模型继续 SFT 有什么风险？

回答方向：

> 基于 instruct 模型继续 SFT 的优势是起点高，指令遵循和对话能力已经较好。但风险是如果数据质量不高或分布过窄，容易破坏原有通用能力，产生过拟合、风格退化、拒答策略异常等问题。因此需要控制学习率、epoch 和数据质量，并做通用能力回归评测。

# 十一、SFT 与 RAG / DPO / RLHF 对比类问题

## 23. 什么时候用 SFT，什么时候用 RAG？

高频问题。

回答方向：

> 如果目标是改变模型行为模式、输出风格、任务格式和指令遵循能力，SFT 更合适。如果目标是注入频繁变化的外部知识，RAG 更合适。SFT 不适合作为动态知识库，因为模型参数更新成本高，且容易产生事实过期问题。

---

## 24. SFT 和 DPO 有什么区别？

回答方向：

> SFT 学习的是标准答案，目标是让模型模仿高质量 response；DPO 学习的是偏好对比，目标是让模型更偏向 preferred answer 而远离 rejected answer。通常 SFT 用于建立基础任务能力，DPO 用于进一步优化回答偏好、风格、安全性和用户满意度。

---

## 25. SFT 后是否还需要 DPO？

可能回答：

> 如果 SFT 后模型已经能完成任务，但回答风格、偏好、安全性、简洁性还有问题，可以进一步做 DPO。如果任务只需要稳定格式输出或领域问答，未必一定需要 DPO。
