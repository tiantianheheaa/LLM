下面按 **SFT Qwen3 模型训练** 的实际使用场景，把这些参数分组讲解：**含义、影响、常规值、推荐配置**。

你给的参数里有两个拼写小问题：

```text
warup_ratio -> warmup_ratio
save_stratety -> save_strategy
```

下面按正确名称讲。

---

# 0. 参数分组总览

可以把这些参数分成 7 类：

| 类别 | 参数 |
|---|---|
| 精度与显存 | `fp16`、`bf16`、`gradient_checkpointing` |
| 学习率与优化器 | `learning_rate`、`warmup_ratio`、`lr_scheduler_type`、`optim`、`weight_decay`、`max_grad_norm` |
| Batch 与梯度累积 | `per_device_train_batch_size`、`gradient_accumulation_steps` |
| 训练轮数 | `num_train_epochs` |
| 保存策略 | `save_strategy` |
| 数据加载 | `dataloader_num_workers` |
| 评估配置 | `eval_strategy`、`per_device_eval_batch_size`、`eval_accumulation_steps`、`label_names` |

---

# 1. 精度与显存相关参数

## 1.1 `fp16`

### 含义

`fp16` 表示使用 **半精度 float16** 训练。

```yaml
fp16: true
```

开启后，部分计算会用 float16，从而：

- 降低显存占用；
- 提升训练速度；
- 但数值稳定性比 bf16 差一些。

---

### 常见问题

`fp16` 的动态范围比较小，训练大模型时可能出现：

```text
loss scale overflow
梯度溢出
loss nan
训练不稳定
```

尤其是 SFT 大模型时，如果硬件支持 bf16，通常更推荐 bf16。

---

### 常规值

| 场景 | fp16 |
|---|---|
| A100/H100/部分新卡支持 bf16 | `false` |
| V100/T4 等不支持 bf16 | `true` |
| Qwen3 SFT，H100/A100 | 一般不用 `fp16`，用 `bf16` |

---

## 1.2 `bf16`

### 含义

`bf16` 表示使用 **bfloat16** 训练。

```yaml
bf16: true
```

bf16 和 fp16 一样都是 16 位精度，但 bf16 的指数范围更大，因此数值稳定性更好。

---

### 为什么 Qwen3 SFT 更推荐 bf16？

对于大模型训练，bf16 通常比 fp16 更稳：

| 精度 | 显存 | 速度 | 稳定性 |
|---|---:|---:|---:|
| fp32 | 高 | 慢 | 最稳 |
| fp16 | 低 | 快 | 可能溢出 |
| bf16 | 低 | 快 | 更稳 |

如果你用的是：

```text
A100 / H100 / H800 / A800
```

一般推荐：

```yaml
bf16: true
fp16: false
```

---

### 常规值

```yaml
bf16: true
fp16: false
```

注意：

> `fp16` 和 `bf16` 通常不要同时设为 `true`。

---

# 2. 学习率与优化器相关参数

这一组决定模型怎么更新参数。

包括：

```text
learning_rate
warmup_ratio
lr_scheduler_type
optim
weight_decay
max_grad_norm
```

---

## 2.1 `learning_rate`

### 含义

`learning_rate` 是学习率，控制参数每次更新的步长。

简单理解：

```text
学习率越大，模型学得越快，但越容易不稳定；
学习率越小，模型更稳定，但可能学不动。
```

---

### 常规值

要区分 **全参数 SFT** 和 **LoRA/QLoRA SFT**。

## 全参数 SFT

全参数微调时，所有模型参数都会更新，因此学习率要小。

常见范围：

```text
5e-6 ~ 2e-5
```

推荐起点：

```yaml
learning_rate: 1e-5
```

更稳：

```yaml
learning_rate: 5e-6
```

---

## LoRA / QLoRA SFT

LoRA 只训练 adapter 参数，因此学习率可以大一些。

常见范围：

```text
5e-5 ~ 2e-4
```

推荐起点：

```yaml
learning_rate: 1e-4
```

如果数据比较少、质量高、怕过拟合：

```yaml
learning_rate: 5e-5
```

如果数据量较大：

```yaml
learning_rate: 1e-4
```

或者：

```yaml
learning_rate: 2e-4
```

---

### 推荐表

| 训练方式 | learning_rate 推荐值 |
|---|---:|
| 全参数 SFT | `5e-6 ~ 1e-5` |
| LoRA SFT | `5e-5 ~ 2e-4` |
| QLoRA SFT | `5e-5 ~ 2e-4` |
| 小数据 SFT | 偏小，例如 `5e-5` LoRA / `5e-6` 全参 |
| 大数据 SFT | 可适当偏大 |

---

## 2.2 `warmup_ratio`

### 含义

`warmup_ratio` 是学习率预热比例。

例如：

```yaml
warmup_ratio: 0.03
```

表示前 3% 的训练 step 用来 warmup。

在 warmup 阶段，学习率会从很小逐渐升到设置的 `learning_rate`。

---

### 为什么需要 warmup？

SFT 初期模型对梯度比较敏感，如果一开始就用完整学习率，可能导致：

```text
loss 抖动
loss nan
训练不稳定
模型输出格式变差
```

warmup 可以让训练更平滑。

---

### 常规值

```text
0.01 ~ 0.1
```

推荐起点：

```yaml
warmup_ratio: 0.03
```

如果总训练 step 较少，可以调大一些：

```yaml
warmup_ratio: 0.05
```

甚至：

```yaml
warmup_ratio: 0.1
```

---

### 推荐表

| 场景 | warmup_ratio |
|---|---:|
| 常规 SFT | `0.03` |
| 总 step 很多 | `0.01 ~ 0.03` |
| 总 step 很少 | `0.05 ~ 0.1` |
| 全参数 SFT | `0.03 ~ 0.05` |
| LoRA/QLoRA | `0.03 ~ 0.05` |

---

## 2.3 `lr_scheduler_type`

### 含义

`lr_scheduler_type` 是学习率调度策略，决定学习率在训练过程中如何变化。

常见过程是：

```text
先 warmup 升高
再逐渐 decay 降低
```

---

### 常见取值

```yaml
lr_scheduler_type: linear
```

```yaml
lr_scheduler_type: cosine
```

```yaml
lr_scheduler_type: constant
```

```yaml
lr_scheduler_type: constant_with_warmup
```

---

## `linear`

学习率 warmup 后线性下降到 0。

特点：

- 稳定；
- 最常用；
- 适合绝大多数 SFT。

推荐：

```yaml
lr_scheduler_type: linear
```

---

## `cosine`

学习率 warmup 后按余弦曲线下降。

特点：

- 后期下降更平滑；
- 长训练时效果可能更好；
- 很多大模型 SFT 会用。

推荐：

```yaml
lr_scheduler_type: cosine
```

---

## `constant`

学习率恒定不变。

特点：

- 简单；
- 但大模型 SFT 中不如 linear/cosine 稳；
- 不太推荐作为默认值。

---

## `constant_with_warmup`

先 warmup，然后保持学习率不变。

特点：

- LoRA 小规模训练可以用；
- 全参数 SFT 一般更推荐 linear/cosine。

---

### 推荐值

| 场景 | 推荐 |
|---|---|
| 不确定怎么选 | `linear` |
| 常规 SFT | `linear` 或 `cosine` |
| 训练 step 较多 | `cosine` |
| 稳定优先 | `linear` |
| LoRA/QLoRA | `linear` 或 `cosine` |
| 全参数 SFT | `linear` 或 `cosine` |

我的建议：

```yaml
lr_scheduler_type: cosine
```

或：

```yaml
lr_scheduler_type: linear
```

第一次实验可以先用：

```yaml
lr_scheduler_type: linear
```

---

## 2.4 `optim`

### 含义

`optim` 指定优化器类型。

优化器决定如何根据梯度更新参数。

---

### 常见取值

不同框架支持的名称略有差异，HuggingFace 常见包括：

```yaml
optim: adamw_torch
```

```yaml
optim: adamw_hf
```

```yaml
optim: paged_adamw_8bit
```

```yaml
optim: paged_adamw_32bit
```

```yaml
optim: adamw_bnb_8bit
```

---

## `adamw_torch`

PyTorch 官方 AdamW。

特点：

- 稳定；
- 通用；
- 全参数 SFT 常用。

推荐：

```yaml
optim: adamw_torch
```

---

## `paged_adamw_8bit`

bitsandbytes 的 8bit paged AdamW。

特点：

- 显存占用更低；
- 常用于 QLoRA；
- 对大模型单机多卡友好。

推荐用于 QLoRA：

```yaml
optim: paged_adamw_8bit
```

---

## `paged_adamw_32bit`

paged AdamW，但优化器状态是 32bit。

特点：

- 比 8bit 更稳；
- 显存比普通 AdamW 低一些；
- QLoRA/LoRA 都可以用。

---

### 推荐表

| 场景 | optim 推荐 |
|---|---|
| 全参数 SFT | `adamw_torch` |
| LoRA SFT | `adamw_torch` 或 `paged_adamw_8bit` |
| QLoRA SFT | `paged_adamw_8bit` |
| 显存紧张 | `paged_adamw_8bit` |
| 稳定性优先 | `adamw_torch` 或 `paged_adamw_32bit` |

---

## 2.5 `weight_decay`

### 含义

`weight_decay` 是权重衰减，是一种正则化手段，用于减少过拟合。

简单理解：

```text
防止模型参数变得过大，让模型不要过度记住训练集。
```

---

### 常规值

```text
0 ~ 0.1
```

SFT 常用：

```yaml
weight_decay: 0.01
```

---

### 推荐表

| 场景 | weight_decay |
|---|---:|
| 常规 SFT | `0.01` |
| 全参数 SFT | `0.01` |
| LoRA/QLoRA | `0.0 ~ 0.01` |
| 小数据、怕过拟合 | `0.01 ~ 0.05` |
| 格式学习、领域强适配 | `0.0 ~ 0.01` |

默认建议：

```yaml
weight_decay: 0.01
```

---

## 2.6 `max_grad_norm`

### 含义

`max_grad_norm` 是梯度裁剪阈值。

例如：

```yaml
max_grad_norm: 1.0
```

表示如果梯度范数超过 1.0，就把它裁剪到 1.0 附近。

---

### 作用

它可以防止梯度爆炸，让训练更稳定。

如果学习率偏大、batch 较小、数据噪声较多，梯度裁剪尤其重要。

---

### 常规值

```yaml
max_grad_norm: 1.0
```

常见范围：

```text
0.3 ~ 1.0
```

推荐：

| 场景 | max_grad_norm |
|---|---:|
| 常规 SFT | `1.0` |
| 训练不稳定 | `0.5` |
| loss 抖动明显 | `0.3 ~ 0.5` |
| 稳定且 batch 大 | `1.0` |

默认建议：

```yaml
max_grad_norm: 1.0
```

---

# 3. Batch 与梯度累积相关参数

这一组决定每一步训练实际看多少样本。

包括：

```text
per_device_train_batch_size
gradient_accumulation_steps
```

---

## 3.1 `per_device_train_batch_size`

### 含义

每张 GPU 上单次 forward/backward 的 batch size。

例如：

```yaml
per_device_train_batch_size: 2
```

如果你有 8 张 GPU，那么单步物理 batch 是：

```text
2 * 8 = 16
```

---

### 显存影响

这个参数对显存影响非常明显。

越大：

- 显存占用越高；
- 吞吐更好；
- 训练更稳定。

越小：

- 显存压力小；
- 但梯度噪声更大；
- 需要配合 `gradient_accumulation_steps`。

---

### 常规值

对于 Qwen3 SFT，常见：

| 模型/方式 | per_device_train_batch_size |
|---|---:|
| Qwen3-8B LoRA/QLoRA | `1 ~ 4` |
| Qwen3-8B 全参 | `1 ~ 2` |
| Qwen3-14B LoRA/QLoRA | `1 ~ 2` |
| Qwen3-30B+ LoRA/QLoRA | `1` |
| 长上下文训练 | `1` |

如果显存够：

```yaml
per_device_train_batch_size: 2
```

如果显存紧张：

```yaml
per_device_train_batch_size: 1
```

---

## 3.2 `gradient_accumulation_steps`

### 含义

梯度累积步数。

如果：

```yaml
gradient_accumulation_steps: 8
```

表示连续 8 个 mini-batch 只累积梯度，不更新参数，第 8 次之后才执行一次 optimizer step。

---

### 为什么需要梯度累积？

当显存不够时，`per_device_train_batch_size` 不能设太大。

这时可以用梯度累积来模拟更大的 batch size。

---

### 有效 batch size 公式

有效 batch size：

```text
global_batch_size =
per_device_train_batch_size
* GPU 数量
* gradient_accumulation_steps
```

如果还有 sequence packing，实际 token batch 还会受样本长度影响。

---

### 示例

假设：

```yaml
per_device_train_batch_size: 2
gradient_accumulation_steps: 8
```

GPU 数量是 8，那么：

```text
global_batch_size = 2 * 8 * 8 = 128
```

---

### 常规值

```text
1 ~ 32
```

推荐：

| 场景 | gradient_accumulation_steps |
|---|---:|
| 显存充足 | `1 ~ 4` |
| 显存一般 | `4 ~ 16` |
| 大模型/长上下文 | `8 ~ 32` |
| 单卡 LoRA | `8 ~ 32` |
| 多卡 H100 | `2 ~ 8` |

默认可从：

```yaml
gradient_accumulation_steps: 8
```

开始。

---

# 4. 训练轮数参数

## 4.1 `num_train_epochs`

### 含义

训练完整遍历数据集的轮数。

```yaml
num_train_epochs: 3
```

表示训练集会被完整训练 3 遍。

---

### 影响

轮数越多：

- 模型对训练数据学习更充分；
- 但更容易过拟合；
- 也更容易出现灾难性遗忘。

---

### 常规值

SFT 常见：

```text
1 ~ 3
```

推荐表：

| 数据规模 | num_train_epochs |
|---|---:|
| 大规模 SFT，几十万/百万样本 | `1` |
| 中等数据，几万样本 | `2 ~ 3` |
| 小数据，几千样本 | `3 ~ 5`，但要看 eval |
| 高质量领域数据 | `2 ~ 3` |
| 格式学习数据 | `1 ~ 3` |

---

### 建议

如果是大模型 SFT，默认建议：

```yaml
num_train_epochs: 3
```

如果数据量很大：

```yaml
num_train_epochs: 1
```

如果担心过拟合：

```yaml
num_train_epochs: 1
```

或：

```yaml
num_train_epochs: 2
```

---

# 5. 保存策略参数

## 5.1 `save_strategy`

### 含义

`save_strategy` 决定模型 checkpoint 什么时候保存。

常见值：

```yaml
save_strategy: steps
```

```yaml
save_strategy: epoch
```

```yaml
save_strategy: "no"
```

---

## `steps`

按训练 step 间隔保存。

通常配合：

```yaml
save_steps: 500
```

例如每 500 step 保存一次。

适合：

- 训练时间长；
- 希望中途恢复；
- 希望挑选最佳 checkpoint。

推荐：

```yaml
save_strategy: steps
```

---

## `epoch`

每个 epoch 结束保存一次。

适合：

- 数据量不大；
- epoch 数较少；
- 不想保存太多 checkpoint。

推荐：

```yaml
save_strategy: epoch
```

---

## `no`

不保存中间 checkpoint。

只适合临时测试，不推荐正式训练。

---

### 推荐值

| 场景 | save_strategy |
|---|---|
| 正式训练 | `steps` |
| 小数据训练 | `epoch` |
| 长时间训练 | `steps` |
| 临时 debug | `no` |

正式训练建议：

```yaml
save_strategy: steps
save_steps: 500
save_total_limit: 3
```

---

# 6. 数据加载参数

## 6.1 `dataloader_num_workers`

### 含义

数据加载时使用多少个子进程。

```yaml
dataloader_num_workers: 4
```

表示用 4 个 worker 并行加载数据。

---

### 影响

如果设太小：

```text
GPU 等数据，吞吐下降
```

如果设太大：

```text
CPU/内存压力增大
可能出现 dataloader 卡顿或死锁
```

---

### 常规值

```text
0 ~ 8
```

推荐：

| 场景 | dataloader_num_workers |
|---|---:|
| 小数据/调试 | `0` |
| 常规训练 | `4` |
| 数据预处理较重 | `4 ~ 8` |
| 多机多卡 | `2 ~ 8` |
| 数据已预处理好 | `2 ~ 4` |

默认建议：

```yaml
dataloader_num_workers: 4
```

如果遇到 dataloader 问题，可以先设：

```yaml
dataloader_num_workers: 0
```

排查问题。

---

# 7. 评估相关参数

包括：

```text
eval_strategy
per_device_eval_batch_size
eval_accumulation_steps
label_names
```

---

## 7.1 `eval_strategy`

### 含义

`eval_strategy` 决定什么时候做验证集评估。

有些版本中也叫：

```yaml
evaluation_strategy
```

常见值：

```yaml
eval_strategy: steps
```

```yaml
eval_strategy: epoch
```

```yaml
eval_strategy: "no"
```

---

## `steps`

每隔一定 step 评估一次。

通常配合：

```yaml
eval_steps: 500
```

适合正式训练。

---

## `epoch`

每个 epoch 结束评估一次。

适合数据较小、训练轮次较明确的场景。

---

## `no`

不做评估。

适合快速 debug，但正式训练不建议。

---

### 推荐值

| 场景 | eval_strategy |
|---|---|
| 正式训练 | `steps` |
| 小数据训练 | `epoch` |
| 快速调试 | `no` |

推荐：

```yaml
eval_strategy: steps
eval_steps: 500
```

如果数据小：

```yaml
eval_strategy: epoch
```

---

## 7.2 `per_device_eval_batch_size`

### 含义

每张 GPU 上评估时的 batch size。

评估时不需要反向传播，所以显存占用一般比训练低，可以设得比训练 batch 大。

---

### 常规值

```text
1 ~ 16
```

推荐表：

| 场景 | per_device_eval_batch_size |
|---|---:|
| 大模型/长上下文 | `1 ~ 2` |
| 8B LoRA | `2 ~ 8` |
| 显存充足 | `8 ~ 16` |
| 显存紧张 | `1` |

默认建议：

```yaml
per_device_eval_batch_size: 1
```

或：

```yaml
per_device_eval_batch_size: 2
```

如果 eval OOM，就降到 1。

---

## 7.3 `eval_accumulation_steps`

### 含义

评估时累计多少 step 的输出后再搬到 CPU。

```yaml
eval_accumulation_steps: 10
```

用于防止评估过程中显存/内存爆掉。

---

### 什么时候需要？

如果 eval 阶段保存 logits、预测结果，可能占用大量显存。

设置 `eval_accumulation_steps` 可以让框架定期清理 GPU 上的评估缓存。

---

### 常规值

```text
1 ~ 20
```

推荐：

| 场景 | eval_accumulation_steps |
|---|---:|
| eval 不 OOM | 不设或 `None` |
| eval 显存高 | `1 ~ 10` |
| 长文本评估 | `1 ~ 4` |
| 大验证集 | `10 ~ 20` |

默认可以不设。

如果 eval OOM，设：

```yaml
eval_accumulation_steps: 10
```

更保守：

```yaml
eval_accumulation_steps: 1
```

---

## 7.4 `label_names`

### 含义

`label_names` 告诉 Trainer：哪些输入字段是 label。

在 HuggingFace Trainer 中，有些模型 forward 需要知道 label 字段名。

对于 causal language modeling / SFT，常见 label 字段是：

```yaml
label_names:
  - labels
```

---

### SFT 中 labels 是什么？

SFT 通常会把输入构造成：

```text
input_ids
attention_mask
labels
```

其中：

- `input_ids` 是模型输入；
- `labels` 是要预测的目标；
- 不参与 loss 的位置通常设为 `-100`。

例如只训练 assistant 回复时：

```text
用户 prompt 部分 labels = -100
assistant answer 部分 labels = token id
```

---

### 常规值

对于标准 SFT：

```yaml
label_names:
  - labels
```

但很多框架会自动处理，不手动配置也可以。

---

### 什么时候需要显式设置？

以下情况建议设置：

```yaml
label_names:
  - labels
```

- 使用 HuggingFace Trainer；
- 使用自定义 dataset；
- 出现 Trainer 找不到 labels；
- loss 没有正常计算；
- 使用 PEFT/LoRA 时 warning 提示 label_names 缺失。

# 8. `gradient_checkpointing`

这个参数虽然属于显存优化，但它和 batch size 强相关，单独展开一下。

## 8.1 含义

`gradient_checkpointing` 是梯度检查点。

```yaml
gradient_checkpointing: true
```

开启后，训练时不会保存所有中间激活，而是在反向传播时重新计算一部分激活。

---

## 8.2 作用

优点：

```text
显著降低显存
可以支持更大模型、更长上下文、更大 batch
```

缺点：

```text
训练速度变慢
通常慢 10% ~ 30%
```

---

## 8.3 常规值

对于大模型 SFT，通常建议开启：

```yaml
gradient_checkpointing: true
```

尤其是：

- Qwen3-8B 以上；
- 长上下文；
- 全参数 SFT；
- 显存紧张；
- batch size 只能设很小。

---

### 推荐表

| 场景 | gradient_checkpointing |
|---|---|
| 显存紧张 | `true` |
| 全参数 SFT | `true` |
| QLoRA/LoRA 大模型 | `true` |
| 小模型且显存充足 | `false` 可提升速度 |
| 长上下文 | `true` |

默认建议：

```yaml
gradient_checkpointing: true
```

# 10. 参数之间的关键关系

## 10.1 `per_device_train_batch_size` 和 `gradient_accumulation_steps`

这两个共同决定有效 batch size：

```text
global_batch_size =
per_device_train_batch_size
* GPU数量
* gradient_accumulation_steps
```

例如：

```yaml
per_device_train_batch_size: 1
gradient_accumulation_steps: 8
```

如果有 8 张 GPU：

```text
global_batch_size = 1 * 8 * 8 = 64
```

---

## 10.2 `learning_rate` 和 batch size

一般来说：

```text
batch 越大，learning_rate 可以略大；
batch 越小，learning_rate 应该更保守。
```

如果你把 global batch 从 64 提到 256，可以考虑适当增大学习率。

但 SFT 场景不建议盲目线性放大学习率，优先稳定。

---

## 10.3 `warmup_ratio` 和总 step

如果总 step 很少：

```text
warmup_ratio 太小，warmup step 可能只有几步，没意义
```

所以小数据短训练可以用：

```yaml
warmup_ratio: 0.05
```

或：

```yaml
warmup_ratio: 0.1
```

---

## 10.4 `bf16`、`gradient_checkpointing` 和 batch size

如果显存不够，优先顺序一般是：

```text
1. 开 bf16
2. 开 gradient_checkpointing
3. 降 per_device_train_batch_size
4. 增 gradient_accumulation_steps
5. 使用 LoRA/QLoRA
6. 使用 ZeRO / DeepSpeed
```
